# asm

CLI-менеджер AIR SDK, версия `1.0.0`. Текущий Windows-прототип состоит из
`asm.bat` для команд и `sdk.ps1` для работы с настройками, каталогом и SDK.
Используется встроенный Windows PowerShell.

Из папки проекта в PowerShell:

```powershell
.\asm.bat help
.\asm.bat --version
.\asm.bat list
.\asm.bat search
.\asm.bat search 51.4
.\asm.bat update
.\asm.bat install 51.4
```

В cmd можно писать `asm help`, `asm --version` и `asm list`. Вызов без аргументов
показывает справку. Также работают `-h`, `--help`, `-v`, `ls`, `help list` и `list --help`.
`--version` и `-v` выводят только `1.0.0`.

`list` читает `%USERPROFILE%\.airsdk\airsdkmanager.cfg` и берёт каталог из `AIR_SDKS`:

```ini
AIR_SDKS=C:\AIRSDK
```

SDK ищутся в непосредственных подпапках этого каталога, как в AIR SDK Manager.
Версия берётся из `air-sdk-description.xml`: например, `<version>51.3.4</version>`
и `<build>1</build>` дают `51.3.4.1`. Список сортируется по числовым компонентам версии.

Пример вывода:

```text
50.2.5.1       C:\AIRSDK\AIRSDK_50.2.5
51.3.3.2       C:\AIRSDK\AIRSDK_51.3.3
51.3.4.1       C:\AIRSDK\AIRSDK_51.3.4
```

Если настройки, значение `AIR_SDKS` или указанный каталог отсутствуют, команда
сообщает об ошибке в stderr и возвращает `1`. Пустой каталог даёт сообщение об
отсутствии SDK и код `0`. Повреждённые описания SDK пропускаются с предупреждением.
Чтение списка не изменяет конфиг AIR SDK Manager.

`search` получает опубликованные стабильные версии из [официального архива AIR SDK](https://airsdk.dev/news/archive):

```powershell
.\asm.bat search
.\asm.bat search 51.4
.\asm.bat search 51.4.1.1
```

Выводятся полные номера SDK, от новых к старым. Фильтр сравнивает компоненты:
`51.4` включает сборки этой ветки и не совпадает с `51.40`.
Для справки работают `help search` и `search --help`.

Архив анонсов загружается небольшим запросом и включает свежие релизы. Некоторые
старые сборки без отдельных анонсов могут отсутствовать. Бета-версии исключаются.
Основной API HARMAN сейчас возвращает серверную ошибку `Sandbox.Timedout`, поэтому
по умолчанию его не опрашиваем перед каждым поиском. Лимит запроса — 15 секунд.

Если источник недоступен, используется каталог из
`%USERPROFILE%\.airsdk\airsdkmanager.db` либо свежей резервной копии этой базы.
Сообщение в stderr указывает источник кеша; такой результат может быть устаревшим.
Если доступного каталога нет, команда возвращает ошибку. Явное поле `API_ENDPOINT`
в настройках менеджера переключает источник каталога на указанный API.

`install` устанавливает SDK в каталог `AIR_SDKS` из настроек AIR SDK Manager:

```powershell
.\asm.bat install 51.4
.\asm.bat install 51.4.1.1
.\asm.bat install latest
```

Сокращённый номер выбирает последнюю стабильную сборку из каталога; `latest` —
последнюю стабильную версию. Полный номер запрашивается напрямую, поэтому можно
установить и сборку без отдельного анонса. Для `51.4.1.1` создаётся папка
`AIR_SDKS\AIRSDK_51.4.1.1`; отсутствующий корень `AIR_SDKS` создаётся автоматически.

Повторная установка уже имеющейся сборки завершается успешно и показывает её путь,
в том числе если SDK лежит в папке с произвольным именем. Занятая целевая папка
с другими файлами вызывает ошибку. Скачивание, проверка SHA-256, выбор Windows
архива и распаковка общие с `update`; готовая папка появляется после всех проверок.
Справка: `asm help install` или `asm install --help`.

`update` без аргументов показывает доступные обновления установленных SDK:

```powershell
.\asm.bat update
.\asm.bat update 51.3 --check
.\asm.bat update --all
.\asm.bat update 51.3
.\asm.bat update 51.3.4.1
```

`--all` обновляет все подходящие установки; номер выбирает уже установленный SDK
или несколько SDK по префиксу. `--check` показывает результат без скачивания и
замены файлов. Номер и `--all` одновременно использовать нельзя. Справка:
`asm help update` или `asm update --help`.

Как AIR SDK Manager, обновляем сборки в рамках первых трёх компонентов:
`51.3.4.1` → `51.3.4.3`. Установленные `51.3.3` и `51.3.4` остаются отдельными SDK.
Обновление сохраняет путь SDK, `lib/adt.cfg` и `lib/adt.lic`.

Архивы проверяются по SHA-256 и собираются в отдельной папке. По умолчанию
скачивается полный Windows ZIP из каталога shockpkg и его зеркала archive.org.
Если явно выбран `API_ENDPOINT`, используется манифест этого API либо точный
манифест из базы менеджера. Из компонентного рецепта исключаются `linux` и `macos`;
общие инструменты, Windows, Android и iPhone сохраняются для сборки с Windows.
Новая установка заменяет старую после проверки структуры; резервные копии остаются
в `AIR_SDKS\.asm-backups`, скачанные архивы — в `%USERPROFILE%\.airsdk\asm-cache`.
При ошибке скачивания или проверки исходный SDK сохраняется. В `--all` после ошибки
дальнейшие установки не обновляются; уже завершённые обновления сохраняются.

Для скачивания нужно принятие соглашения AIR SDK. Читаем `HAS_ACCEPTED_LICENSE`
из настроек менеджера; если оно ещё не принято, используйте `--accept-license`.
Конфиг менеджера и его база не перезаписываются.

План остальных команд и кроссплатформенной версии — в [plan.md](plan.md).
